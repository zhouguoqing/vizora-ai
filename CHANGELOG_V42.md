# Vizora AI V4.2 — Identity and Entitlement Hardening

## Delivered
- Email ownership verification: one-time 30-minute link, SHA-256 token digest stored in PostgreSQL.
- Verification resend, forgot password, reset password, login blocked before verification.
- JWT server-side token version enforcement and logout-all endpoint; password reset invalidates earlier sessions.
- SMTP settings for actual transactional delivery (requires real provider setup).
- Vue workflows for verify, resend, forgot, and reset.
- Entitlement grants keyed by order; successful gateway refund reconciliation now revokes associated grant.
- If the only grant is refunded, membership expiry is set to now. If purchases overlap, create a manual review record rather than guessing how to shorten remaining service.

## Limitations / do not open production billing yet
- Could not run dotnet build (SDK unavailable). Frontend build failed due to dependencies missing (`vue-tsc` unavailable). Unit checks are static only.
- Need real SMTP delivery testing with mail provider and security verification of forwarded headers, TLS, credential rotation, brute-force protection and email rate limiting.
- Account email verification/resend send failures may be logged but response intentionally avoids account enumeration.
- Need migration against a cloned production database and confirm how previously created unverified accounts will be handled.
- Refunds of stacked memberships require human financial review. No automatic multi-grant validity recomputation; do not represent refund reconciliation as finished until review is resolved.
- Need explicit consent checkbox and appropriate legal texts (not autogenerated placeholder policy), CAPTCHA, account deletion export, audit events, chargeback handling.
- Payment reconciliation job, gateway authenticity, receipt reconciliation and true real-money test are unverified.
- Need security, load, browser e2e tests and deploy/rollback dry run.

## Required setup
1. Configure SMTP via Mail__Host, Mail__Port, Mail__User, Mail__Password, Mail__From.
2. Set Payments__WebBaseUrl to the correct public HTTPS origin for verification links.
3. On a CI worker with .NET 10 and npm network access, run `dotnet build api/Vizora.Api.csproj -c Release`, then `cd web && npm install && npm run build`.
4. Apply `db/schema.sql` in staging first, then test registration and account recovery end to end.
5. Complete production release gate before taking live payments.
