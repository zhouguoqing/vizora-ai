# SMTP 465 Configuration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Send account verification and password-reset email through 163 SMTP on port 465 with implicit TLS, and add automated tests without using real credentials or external mail delivery.

**Architecture:** Replace `System.Net.Mail.SmtpClient` with a small MailKit-backed account mail service. Resolve TLS mode explicitly: port 465 uses implicit TLS, TLS-enabled other ports use STARTTLS, and plaintext is permitted only for loopback SMTP capture in Development. Keep account token/database behavior unchanged and configure only non-secret settings in the ignored local `.env.dev`.

**Tech Stack:** .NET 10, ASP.NET Core Minimal API, MailKit, xUnit, existing PostgreSQL/API integration runner and loopback SMTP capture.

- [ ] **Step 2: Implement the pure security-mode resolver**

Implement a deterministic resolver that:

```csharp
if (enableSsl && port == 465) return SecureSocketOptions.SslOnConnect;
if (enableSsl) return SecureSocketOptions.StartTls;
if (environmentIsDevelopment && hostIsLoopback) return SecureSocketOptions.None;
throw new InvalidOperationException("SMTP TLS is required outside loopback Development");
```

Validate host and port before connecting; never fall back from TLS to plaintext after a negotiation error.

- [ ] **Step 3: Implement `IAccountMailer` using MailKit**

Connect using the resolved `SecureSocketOptions`, authenticate only when the configured username is non-empty, send a `MimeMessage` using the configured sender, then disconnect cleanly. Let transport errors propagate to the existing account-mail error boundary so the API continues returning an explicit failure and logging only the exception type.
